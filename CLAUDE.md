# Sensybull API

## Tech Stack
- Flask 2.3, SQLAlchemy 2.0, PostgreSQL (SQLite fallback), Redis pub/sub
- JWT auth (Flask-JWT-Extended), Resend for transactional email
- Flask-SocketIO (gevent) for real-time filing event delivery
- Ingest pipeline: SEC EDGAR polling → Groq LLM briefing → Redis → API. A second poller in the same worker (`services/ingest/press_release/`, flag `PR_INGEST_ENABLED`, off by default) ingests newswire press releases (GlobeNewswire/PR Newswire RSS; Business Wire/Accesswire only via `PR_FEED_URLS_<WIRE>` — no confirmed public feed): promo prefilter + law-firm blocklist + issuer-vs-ticker verification + LLM first-party/materiality gate; publishes `signal_type="PR"` events on the same Redis contract (synthetic `edgar_id="pr:<wire>:<guid>"`, no facts_only fallback — unclassifiable releases are dropped)
- Briefings are a single Groq pass with prompt-level "stick to the filing text" guidance (`briefing.mode = "llm"`). Narrative voice (third person, no "we"/"our", don't inherit the source's promotional framing) lives in one shared `briefing.VOICE_RULES` block that both the 8-K prompt and the press-release prompt embed — filings and wire releases are written in the company's own voice, and the model mirrors it unless told not to. Add voice guidance there, not per-prompt. When the LLM call fails, the model reports insufficient content, or the filing has too little text to summarize, the event publishes as a deterministic facts-only briefing (`mode = "facts_only"`). July 2026: the mechanical grounding checks (`grounding.py`) and second LLM verifier pass were rolled back as net-negative (too many false rejections); historical events may carry `mode = "llm_verified"` / `"structured"`.
- Briefings are evidenced: the same pass asks for up to 3 verbatim supporting quotes, and `services/ingest/evidence.py` verifies each one against the source document (4-word shingles, ≥40% must appear verbatim — the grounding check from arXiv:2607.08346) before storing **the span it matched**, never the model's transcription. Unverifiable quotes are dropped, not retried (one pass, tight TPM budget). Each surviving quote gets a browser text-fragment deep link built by `services/ingest/text_fragment.py`, so clicking it opens the document on sec.gov highlighted at the passage. This is the one part of a briefing that is not model prose — don't let anything downstream edit a quote. Mechanism, browser-support caveats and rejected alternatives: `docs/EVIDENCE_LINKS.md`.

## Project Structure
- `services/api/` — Flask REST API + WebSocket server
- `services/ingest/` — SEC EDGAR polling + LLM briefing pipeline
- Production frontend lives in the separate `sensybull-web` repo (Next.js)

## Product surface notes
- Ingest is 8-K only among SEC forms (July 2026 rollback): the multi-form pipeline (SC 13D/G, tenders, merger/contested proxies, delistings, NT late filings, Form 4 insider buys) was deleted — other form types were too hard to debug. Only `8-K` and `8-K/A` are in `services/ingest/forms.py`. Historical non-8-K events remain in the DB and still serialize normally; don't re-add forms without an explicit decision. Press releases (`signal_type="PR"`) are the one non-EDGAR source (July 2026 decision).
- Event types are a deliberately small list of highly material categories (12 labels incl. "Other"; "Regulatory / Clinical" added with press releases) defined in `services/ingest/briefing.py` EVENT_TYPES and mirrored in `services/api/app/routes/events.py` (`GET /events/types` backs the feed's category filter). Keep the two in sync; don't grow the list casually.
- PR↔8-K dedup lives in the subscriber (`services/api/app/services/realtime/pr_dedup.py`): the same announcement appears once. Cross-wire dups and PRs arriving after their 8-K are dropped; an 8-K arriving after its PR backfills the PR event (`related_filing_url`, emitted as socket `filing_event_update`) and is suppressed when it's a pure wrapper (items ⊆ {2.02, 7.01, 8.01, 9.01} and exhibit fingerprint matches; `PR_SUPPRESS_8K=0` disables suppression). Fingerprint match rule is duplicated in `services/ingest/press_release/fingerprint.py` — keep in sync.
- Deal terms are normalized once, on write: the subscriber runs `app/utils/deal_terms.normalize_deal_terms()` over `briefing.deal_terms` before persisting both storage sites (`filing_event.briefing_json` and `event_type.attributes`), so keys are snake_case and values are Title Cased (figures and acronyms untouched, prose-length values sentence-cased). Prompt guidance asks the model for the same. Rules are mirrored in sensybull-web `src/lib/deal-terms.ts` — keep in sync; `scripts/normalize_deal_terms_case.py` backfills older rows.
- Supporting quotes live at `briefing.evidence` (inside `briefing_json`, so no column and no migration): `[{quote, event_type, source, doc_url, url, highlighted}]`. `doc_url` is the *document* URL from `fetch_filing_detail`'s new `primary_url` (or an exhibit's), not the event's `edgar_url` index page. The subscriber runs `app/utils/evidence.sanitize_evidence()` over it on write — an entry whose URL isn't https-on-sec.gov keeps its quote and loses its link, and `highlighted` falls with it. Evidence is always empty on facts-only briefings and on press releases.
- Priority is binary at the API boundary: `FilingEvent.to_ws_payload()` exposes `important` (briefing significance High → true, else tier-1 fallback). The ingest pipeline still grades High/Medium/Low internally — that stays; only the product surface is binary.
- Thesis monitoring: rolled back July 2026, direction reversed Sept 2026 (see sensybull-web `PRODUCT_VISION.md`), rebuild not started. Today there are still no `/positions` routes, no `services/api/app/services/thesis/`, and no thesis-aware alert formatting — the web landing page sells the feature ahead of the API. The `position` / `thesis_assessment` / `thesis_version` tables are empty leftovers with no model mapping them; the rebuild should re-map those rather than migrate new ones. Build order and the scope limits are in `PRODUCT_VISION.md` — in particular, the judge must cite a span verified by `services/ingest/evidence.py`, and nothing judges against financial statements (8-Ks don't carry them).
- `GET /events/catalysts` was removed with the catalyst calendar; catalysts are still persisted per event and serialized inside each event payload.
- Market data comes from FMP (Alpaca retired Sept 2026 — one vendor, one key, for fundamentals and prices). `app/services/market_data/prices.py` is the only module that knows FMP's price endpoints (`/batch-quote`, `/historical-price-eod/full`, `/historical-chart/<interval>`); it reuses the fundamentals `FMPClient` for transport, retries and rate limiting, and turns FMP's shapes into ours: bars are `{t,o,h,l,c,v}` with `t` an ISO UTC string ending in `Z`, daily bars stamped at **midnight New York** (the web's `sessionDate()` and the reaction worker read the session from that, and the web's history paging compares `t` as strings — don't change the format), intraday `date`s converted from Eastern wall time to UTC, long intraday windows chunked per `INTRADAY_CHUNK_DAYS`. `flask check-market-data` verifies those assumptions against the live API (timezone, split adjustment, extended hours, batch and chunk caps) — run it after touching `prices.py` or changing the FMP plan. It reaches the frontend through three proxies on `routes/companies.py`, all Redis-cached: `GET /companies/<id>/bars` (chart OHLCV, 5 min — an optional `end` pages backwards through history for the chart's load-on-pan, and those closed windows cache for a day), `GET /companies/<id>/quote` (one company, 60s), and `GET /companies/quotes?ids=a,b,c` (up to `MAX_QUOTE_IDS` companies in one round trip — backs the price shown on every feed and watchlist row). Both quote routes share the `quote:<TICKER>` cache and one payload builder (`_quote_payload`), fold every cache miss into a single `prices.get_quotes()` call, and fall back to the daily-synced `Company.last_price` with `stale: true`. The single route 503s when there's no price at all; the batch route just omits that company. Quote→price reading is `prices.quote_price()`, shared with the daily `sync-market-data` cron. The price-reaction worker (`reaction_worker.py`) starts when `REDIS_URL` and `FMP_API_KEY` are set. FMP's 1-min bars are regular-session only, so a filing's session decides its intraday reactions: filed during the session → `5m`/`15m`/`30m`/`1h`, minus any that land after that session's close (skipped `after_close`); filed outside it (evening, pre-market, weekend, holiday) → one `open` reaction, the next session's opening print — the worker renames the `5m` row and skips the rest (`off_hours`), because all four would read the same bar. `1d`/`1w` are the same for both. Sessions are Eastern dates, never UTC ones (21:00 ET is tomorrow in UTC). `flask reset-reactions --days N` re-queues intraday rows measured under older rules.
- Fundamentals explorer (Sept 2026, screener.in-style company pages — plan in `docs/FUNDAMENTALS_PLAN.md`): statements are **stored, not proxied**. `services/fundamentals/` fetches FMP `/stable` (`fmp_client.py`, field aliases for both FMP generations in `fields.py`), maps three statements per period into `fundamentals_period` (typed columns + the raw records, `mapper.py` sets `quality_flags` from reconciliation checks), computes every page row in `rows.py` (mirrored by sensybull-web `src/lib/fundamentals/rows.ts` — keep keys in sync; US balance sheets are Assets → Liabilities → Equity). All four statements are served at **both** granularities — `quarterly.{income,balance,cashflow,ratios}` and `annual.{…}`, same shape — so the page offers one Quarterly/Annual switch per statement; the quarterly figures cost no extra FMP calls because `sync.py` already fetches all three statements per quarter. A days ratio divides a balance by a flow, so `ratio_rows()` takes `period_days` (`quarter_ratio_rows()` passes the quarter's) and `roce_pct()` annualises by the same ratio — running a quarter through the annual day count reports days four times too high, and derives TTM / CAGRs / header ratios / deterministic pros-cons into `company_fundamentals.derived` (`derive.py`, `analysis.py`). `GET /fundamentals/<symbol>` (public, `routes/fundamentals.py`) serves one column-oriented payload; a never-synced ticker starts an in-process backfill and answers 202 `building`. Cron chain: `sync-fundamentals` (backfill + earnings-calendar refresh + 30-day rolling refresh) then `rebuild-fundamentals` (price-dependent ratios). `GET /companies/search` is public now and ranks by market cap. Only `/stable` paths and field names are pinned in one place each; FMP's misspelled `netCashUsedForInvestingActivites` is an alias, not a typo.
- The watchlist inbox (`routes/watchlist_inbox.py`) has bulk counterparts to its per-company actions — `POST /watchlist/read`, `PUT /watchlist/mute`, `POST /watchlist/remove`, all taking `{company_ids}` — backing the web multi-select. They share `_bulk_target_ids()`, which intersects the request with the companies the caller follows: unknown ids are dropped (a client's list goes stale whenever another tab removes a company), and only an empty intersection is a 403.

- Discovery surface (Sept 2026): `GET /api/v1/discovery/sitemap` (public, Redis-cached 6h) lists companies with a fundamentals page and recent events whose briefing carries evidence — sensybull-web's `sitemap.ts` renders it; only evidence-bearing events are indexable. The API host also serves `/.well-known/api-catalog` (RFC 9727 linkset → `/docs/openapi.json`, `/docs`, `/health`) and a `robots.txt` that keeps crawlers off `/api/`. The OpenAPI spec is what agents read: when you add or change a public route, add it to `app/openapi.py` (routes added after the original spec go in the `OPENAPI_SPEC["paths"].update(...)` block at the bottom; `tests/test_discovery.py` pins the public read routes). No OAuth/OIDC discovery metadata is published on purpose — auth is first-party JWT, and advertising flows that don't exist would break agents that trust it.

## Conventions
- Models extend BaseModel (UUID id, created_at) in `services/api/app/models/`
- Routes are Flask blueprints registered at `/api/v1/<name>`
- Public share surface (`/api/v1/share/*`, `/api/v1/watchlists/track`) backs the frontend's `/add/<symbol>` track links — docs in sensybull-web `docs/TRACK_LINKS.md`
- Schemas use Marshmallow in `services/api/app/utils/schemas.py`
- Email templates require both `.html` and `.txt` in `services/api/app/services/email/templates/`
- Tests in `services/api/tests/`, run with `cd services/api && python -m pytest tests/`
- CI: GitHub Actions (ruff lint + pytest + Docker build)
- Deployed on Render (see `render.yaml`)
